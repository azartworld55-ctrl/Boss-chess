# Boss Chess — технический план

> Статус: план. Перечисленные инструменты не считаются установленными или интегрированными, пока это отдельно не выполнено и не проверено.

## Цели проекта

- В первую очередь проектировать и проверять интерфейс для мобильных телефонов (mobile-first).
- Полностью русскоязычный интерфейс: меню, настройки, уведомления, подсказки и сообщения об ошибках.
- Сохранить полноценную адаптивную версию для планшетов и компьютеров.
- Сделать управление удобным для касаний, без горизонтальной прокрутки и с доской, которая подстраивается под экран.
- Следить за скоростью загрузки, доступностью и стабильностью.
- Сначала довести обычную игру против компьютера; режим боссов — отдельный будущий этап.

## Предварительный выбор и правила против дублирования

Это ориентиры для оценки и будущего внедрения, а не требование установить все пакеты.

| Область | Основной кандидат | Правило использования |
|---|---|---|
| Шахматная доска | Lichess Chessground | Проверить интеграцию с текущим React-приложением и Stockfish до замены доски |
| Шахматная логика | chessops | Сравнить с уже используемым chess.js; не держать две библиотеки для одних и тех же задач без необходимости |
| Иконки | Lucide | Единый набор иконок |
| UI-компоненты | shadcn/ui + Radix UI | shadcn/ui — подход к компонентам, Radix — возможная примитивная основа; не считать их двумя конкурирующими дизайн-системами |
| Доступность компонентов | React Aria | Использовать точечно там, где это даёт преимущество; не дублировать компоненты Radix без причины |
| Основные анимации | Motion | Предпочтительная система для обычных React-анимаций |
| Дополнительные эффекты | React Bits | Выбирать отдельные эффекты, а не подключать всё подряд |
| Сложные/сценические анимации | GSAP | Только если Motion не подходит для конкретной задачи |
| Анимации появления списков | Auto Animate | Использовать точечно; не дублировать анимации Motion |
| Управление состоянием | Zustand | Вводить, если текущее состояние React станет трудно поддерживать |
| Серверные/асинхронные данные | TanStack Query | Подключать при появлении реальных запросов и кешируемых данных; для локальной партии может быть не нужен |
| Уведомления | Sonner | Единый механизм toast-уведомлений |
| 3D-графика | React Three Fiber | Отложить до появления конкретной 3D-функции |
| Автотесты браузера | Playwright | Проверять ключевые пользовательские сценарии на мобильных и настольных размерах |
| Аудит производительности | Lighthouse | Периодически проверять производительность, доступность и SEO |
| Аудит доступности | axe-core | Автоматические проверки доступности вместе с ручной проверкой |
| Обслуживание зависимостей | Renovate | Предлагать обновления зависимостей через pull request |
| CI/CD | GitHub Actions | Сборка, тесты и публикация сайта |
| Статический анализ | ESLint | Проверки кода в локальной разработке и CI |

React Spring не выбран как основная система анимаций: предпочтение отдаётся Motion. Он может быть пересмотрен только при конкретной технической необходимости.

## Предлагаемый порядок работ

1. Проверить текущее состояние приложения и зафиксировать рабочую версию.
2. Спроектировать mobile-first интерфейс на русском языке; сохранить удобную desktop-версию.
3. Отдельно оценить Chessground и chessops на совместимость с текущей логикой и движком.
4. Определить единую основу UI и внедрять Lucide и выбранные компоненты постепенно.
5. Добавлять анимации дозированно, следя за производительностью на телефонах.
6. Настроить Playwright, ESLint и проверки GitHub Actions.
7. Добавить Lighthouse и axe-core в процесс проверки качества.
8. Подключить Renovate после настройки CI.
9. Рассматривать 3D и дополнительные тяжёлые эффекты только при наличии конкретного сценария.

## Критерии при выборе зависимости

Перед добавлением каждой библиотеки проверить:
- совместимость с используемыми версиями React и Vite;
- активность и надёжность проекта;
- лицензию и ограничения использования;
- размер бандла и влияние на мобильную производительность;
- доступность с клавиатуры и сенсорное управление;
- наличие уже реализованной функции в текущем проекте;
- возможность отказаться от зависимости без большой переделки.

## Примечание

Текущий проект уже использует React, Vite, react-chessboard, chess.js и Stockfish. Замена существующих компонентов должна выполняться поэтапно, с проверкой сборки и игровых сценариев. Наличие инструмента в этом документе не означает, что он установлен, подключён или уже проверен.
