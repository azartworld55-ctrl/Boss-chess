# Boss Chess — ежедневный рабочий процесс

Этот документ — инструкция для ежедневных задач проекта. Репозиторий: `azartworld55-ctrl/Boss-chess`.

## Главное направление

Развивать браузерную шахматную игру Boss Chess и её кампанию с боссами. Это не общий игровой проект и не ASHEN DECKS. Любые ежедневные идеи, изменения и проверки должны относиться только к Boss Chess.

Учитывай текущие возможности и существующую архитектуру: обычная шахматная партия против Stockfish, настройки сложности, интерфейс доски и кампания боссов. Глава 1 называется «Классика», первый босс — «Пешка». Не переписывай правила обычной шахматной партии ради кампании. Особые правила кампании должны оставаться изолированными в её модуле.

## Расписание и обязанности

### 02:00 — идея и план обновления

- Изучи актуальную ветку `main`, последние коммиты, открытые PR, заметки в `updates/` и этот документ.
- Выбери ровно одно небольшое, конкретное улучшение Boss Chess, которое реально реализовать и проверить за день.
- Приоритет: корректность шахматных правил, поведение Stockfish и боссов, удобство доски на телефонах, стабильность, доступность, производительность и понятность интерфейса.
- Не повторяй недавние изменения и не выдумывай проблему без проверки кода.
- Создай `updates/YYYY-MM-DD-idea.md` с разделами: проблема, ожидаемый эффект, предлагаемое изменение, точные файлы/области, риски и ограничения, критерии приёмки, тесты.
- Создай ветку `daily/YYYY-MM-DD` от актуального `main` и закоммить в неё только заметку.
- Не меняй игровые файлы, не коммить в `main`, не сливай PR.

### 03:00 — реализация

- Прочитай сегодняшнюю заметку `updates/YYYY-MM-DD-idea.md`.
- Реализуй только описанное в ней изменение в ветке `daily/YYYY-MM-DD`.
- Не добавляй незапрошенные режимы, боссов, способности, визуальные переделки или сторонние функции.
- Не ломай обычные шахматы, кампанию, сохранения и мобильную компоновку.
- Добавь или обнови тесты. Запусти доступные `npm test`, `npm run lint`, `npm run build`.
- Если идея отсутствует или ветка не подготовлена, не придумывай замену и не меняй игровой код.

### 04:00 — проверка и подготовка PR

- Проверь diff относительно `main`, соответствие заметке и критерии приёмки.
- Проверь шахматную логику, специальные правила кампании, регрессии, мобильный интерфейс и сохранения там, где это применимо.
- Запусти тесты, lint и production build. Исправления делай только в сегодняшней daily-ветке и сопровождай тестами.
- Проверь GitHub Actions, если они запустились.
- Если всё действительно прошло, создай или обнови PR в `main` и оставь его на review. Не сливай автоматически.
- Если проверка не завершилась или есть ошибки, укажи точные блокеры. Не называй PR готовым и не ослабляй тесты ради зелёного статуса.

## Правила безопасности изменений

- Не заявляй, что файл изменён, тест пройден или сайт опубликован, пока это не подтверждено результатом инструмента или GitHub Actions.
- Перед обновлением существующего файла получай его актуальный SHA; не делай параллельные записи в один файл.
- Не переписывай историю и не коммить ежедневную работу напрямую в `main`.
- Не добавляй зависимости без реальной необходимости.
- Не меняй ограничения проекта и не расширяй объём задачи без прямого запроса владельца.
- Сохраняй русскоязычный интерфейс и проверяй узкие мобильные экраны.
